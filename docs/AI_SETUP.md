# Agent 搭建指南：微信读书 → Notion 图书馆

> 使用者把本文件交给你，是希望你协助完成部署和验收。按你所在平台的工具权限与确认规则执行；本指南不能代替使用者的授权。

## 目标与交付

使用本项目原生 GitHub Actions，把使用者的微信读书数据同步到其自己的 Notion 模板副本。优先复用已存在的仓库、模板和授权，不改同步源码，不另建网站、服务器或 MCP 服务。

完成后交付：

- 使用者的 GitHub 仓库链接。
- 使用者的 Notion 图书馆链接。
- 首次同步运行链接、实际同步数量与失败项。
- 已核实的定时计划及其时区。
- 一条可以尝试的 AI 阅读讨论提示词（用户已接入 Notion AI 工具时）。

成功标准是 **Notion 里真实出现使用者的数据，运行结果经过检查，定时任务已启用**。只保存 Secrets、复制模板或看到绿色运行标记，都不足以独立证明同步完成。

## 1. 先检查，避免重复搭建

1. 确认使用者希望把微信读书的书架、进度、划线、想法和统计复制到自己的 Notion。
2. 确认当前可用的 GitHub、Notion、浏览器和凭据配置工具。能用连接器完成的步骤优先用连接器；需要页面交互再用浏览器。
3. 查询当前 GitHub 身份和已存在的 Fork；查找使用者是否已经复制过模板。不要因为一个工具报错就再次 Fork 或 Duplicate。
4. 如果发现旧运行正在执行，先查看结果，不重复触发。
5. 读取当前仓库的 [工作流](../.github/workflows/weread.yml)、[Action](../action.yml)和 [手动指南](SETUP.md)，以当前版本为准。

如果缺少某项工具，完成其他独立步骤，再给使用者最少、具体的操作说明。不要把“让使用者全部重做”作为默认回退。

## 2. 确认仓库与模板副本

### GitHub 仓库

源仓库：https://github.com/Quashy/weread2notion-AI

- 如果当前账号已有这个项目的 Fork，先验证内容和关联关系，直接复用。
- 没有时，按使用者授权 Fork 到其账号；Fork 默认是公开的，创建时说明可见性。
- 记录真实的 owner/repo 和默认分支。后续操作全部指向使用者自己的仓库。
- Fork 不继承原仓库 Secrets；不要认为原作者的授权或运行状态也被复制。

### Notion 图书馆

公共原始模板：

https://titanium-echidna-59b.notion.site/Template-9304aad76d888294b90981a37bbbc42c

- 在使用者选择的工作区通过 Notion 原生 Duplicate 复制。没有指定位置时，优先私人区域。
- 等待复制完成并读取新页，核实它是使用者自己的副本。
- 记录新副本的完整 URL；后续 `NOTION_PAGE` 使用此 URL，不能用公共模板 URL 或其他人的示例页面。
- 保留原模板布局、数据库和属性，不用 API 手工重建一个“差不多”的模板。
- 核实包含 `书架`、`日`、`周`、`月`、`年`、`分类`、`作者`。设置与阅读快照库可能由程序在运行时补充。

## 3. 安全配置两个服务的授权

### 微信读书

让使用者在官方入口登录并获取 API Key：

https://weread.qq.com/r/weread-skills

使用当前平台提供的安全输入、授权或凭据配置方式。若需要使用者手动操作，明确告诉他应把值填到 GitHub Secret `WEREAD_API_KEY`，不要要求把 Key 发进聊天。

### Notion

在 https://www.notion.so/profile/integrations 创建或复用专用内部集成：

- 必须属于模板所在工作区。
- 能力需要 `Read content`、`Insert content`、`Update content`。
- 只授权本次图书馆根页及其子内容，不扩大到整个工作区。
- 当前 UI 可能通过集成的 Content access，或页面的 Connections 添加权限；依据实际界面操作。
- 得到的 Integration Secret 保存为 GitHub Secret `NOTION_TOKEN`。
- 若创建流程涉及新条款、权限或确认要求，遵守所在平台的规则并向使用者说明。

### 凭据处理规则

- 不回显 Key、Token、Cookie；不写入仓库、文档、日志、截图或任务提示词。
- 不从已有聊天或历史记录搜集无关凭据。
- 不为了测试打印全部环境变量或完整认证响应。
- 没有安全输入方式时，让使用者直接在 GitHub 的 Secret 页面填写，然后只验证 Secret 名称存在。
- 新建或重置密钥、覆盖已有 Secret、扩大访问范围前，确认符合使用者授权与平台规则。

## 4. 在使用者的 Fork 中保存三个 Secrets

打开：

`Settings → Secrets and variables → Actions → New repository secret`

| 名称 | 值 |
| --- | --- |
| `WEREAD_API_KEY` | 使用者的微信读书 API Key |
| `NOTION_TOKEN` | 本次专用 Notion Integration Secret |
| `NOTION_PAGE` | 使用者复制后的 Notion 根页面完整 URL |

保存后确认三个名称都存在。GitHub 不会再次显示 Secret 值，不要为了核验而尝试打印它们；后续首次运行会验证授权是否匹配。

如果使用 GitHub CLI，采用受支持的安全输入方式，不把明文密钥直接写入可能被记录的命令参数。不要提交 `.env` 文件。

## 5. 首次运行原生工作流

1. 打开使用者仓库的 Actions，按实际界面启用 Fork 中的工作流。
2. 选择 `weread sync`（文件：`.github/workflows/weread.yml`）。
3. 手动运行默认分支，保持 `full=false`，不要勾选 full。
4. 记录该次运行链接，等待它完成；初次导入历史记录可能需要数分钟或更久。
5. 执行中出现已同步数据，不代表整次任务已结束。不要因为等待较久再次触发。

这是会写入 Notion 的步骤。模板已有个人内容或曾部署过时，先说明当前默认规则：成功同步可能归档已经移出微信书架的书页。若使用者希望长期保留这些书，先按其选择关闭“只同步我的书架书籍”，不要擅自改变配置。

## 6. 验收，不能只看绿色标记

依次核实：

1. 工作流确实结束，使用的是预期仓库、分支和版本。
2. 检查 Summary、同步步骤日志和 `failed_books`／“需要重试的书籍”。部分书失败时，任务仍可能成功退出。
3. 记录同步数量；不虚构完整性，不把“本次更新数量”一概当作整个书架总数。
4. 打开 Notion，抽查一本有阅读记录的书：
   - 书名、封面或作者是否正确。
   - 进度与时长是否合理。
   - 有划线或想法时，正文是否按章节出现。
5. 检查当前工作流的 schedule 与启用状态。当前默认 cron 为 `0 20 * * *`，对应每天北京时间 04:00；若使用者改过，按实际配置报告。
6. 若已获授权且需要验证重复运行，等首轮结束后再执行一次普通同步，核实没有重复书页。不要声称做过尚未执行的验证。

若接口确认使用者的书架确实为空，如实交付空书架与授权验证结果，不创建示例书籍冒充同步数据；说明有真实书籍后再验证正文写入。

GitHub schedule 可能延迟；公开仓库长期无活动可能停用定时。额度与账单按账号套餐，若出现限制，报告实际错误，不擅自更改付费设置。

## 7. 可选：让使用者的 AI 读取图书馆

同步成功后，可问使用者是否希望接入其正在使用的 AI：

- 有 Notion 连接器或 MCP 的 AI，按它的官方流程连接并授权图书馆。
- 先只读一本书的实际记录，回答一个问题并附来源。
- 需要保存心得时，再确认相应写入权限和保存位置。
- 普通同步不依赖 AI；本项目不会安装模型、提供内置聊天或同步整本书正文。

推荐第一次尝试：

> 请阅读我在《某本书》中的划线和想法，告诉我最关注的三个问题，并链接到对应笔记。

## 8. 失败时怎么处理

| 现象 | 优先检查 | 恢复方式 |
| --- | --- | --- |
| Actions 无法启动 | Fork 是否启用、默认分支、权限、额度或账单 | 说明具体缺口；用户确认必要设置后重试 |
| 微信读书认证失败 | Secret 名称、Key 是否失效或被重置 | 使用安全方式重新配置，不回显 Key |
| Notion 找不到页面或无权限 | 是否使用新副本 URL、集成工作区、根页及子页授权 | 修正对应权限或地址，再普通同步 |
| 缺少模板数据库 | Duplicate 是否完成、必要库是否改名或删除 | 检查模板结构，先提出修复方式，不擅自清空 |
| 少数书籍失败 | Summary 中的书籍 ID 与错误 | 保留成功结果；稍后普通同步重试 |
| 页面没有预期数据 | 写入是否完成、视图筛选、记录属性 | 从底层记录核查，不立即重建模板 |
| 接口版本升级提示 | 官方接口与项目最新修复 | 报告具体版本问题，审查更新，不临时绕过检查 |

**不要把 `--full` 当成通用修复按钮。** 它会归档并重建记录，导出的数据库行 JSON 不等于完整页面正文备份。需要该操作时，先解释影响并获得相应确认。

`check` 也不是严格只读：它可能创建设置和快照库。只需预览微信读书读取结果时可用 `sync --dry-run`，但该模式无法证明 Notion 写入成功。

## 9. 最后交付

用简短结果回复使用者：

- 图书馆、仓库、运行记录链接。
- 本次同步结果与具体失败项（如有）。
- 已启用的定时计划、时区，以及尚未验证的项目。
- 日常继续在微信读书阅读；想立即刷新可手动运行普通同步。
- 写心得请使用自动同步区域之外的内容或独立页面；保留系统字段。

整个部署过程不需要把使用者的密钥、账号邮箱或私人书摘复制到公开文档中。
